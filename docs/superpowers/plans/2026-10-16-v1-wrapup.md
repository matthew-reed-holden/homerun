# v1 Wrap-up Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the remaining code beads of the homerun v1 epic (homerun-7re): .30, .31, .26 (+ homerun-1in.12), .28, .23, .24.

**Architecture:** Six independent, local fixes in `internal/config` and `internal/daemon`. Each task states the behaviour, the decision already taken, where the code is, and the tests that must fail before the fix. Implementers write the code (standard model): these are bug fixes in existing code, so the plan gives requirements and locations rather than full listings.

**Tech Stack:** Go 1.27; existing packages only. Daemon tests use `testdata/fake-act.sh` through `internal/daemon/harness_test.go` (`newHarness`, `h.output`, `h.push`, `h.pr`, `h.poll`, `h.waitDone`, `h.waitStatus`, `h.waitRun`, `h.occupySlots`, `h.setSecret`, `h.rep.failUpdates(n)`, `h.rep.set(failOn, after)`, `h.fake`).

**Spec:** `docs/superpowers/specs/2026-10-12-homerun-design.md` (v1). Bead descriptions in `bd show homerun-7re.<n>`.

## Global Constraints

- Module `github.com/matthew-reed-holden/homerun`. Branch `v1-wrapup`. No new dependencies.
- Check names: `homerun / <workflow> / <job>`; extra checks `homerun / checks / <name>`; setup failures `homerun`.
- Failures caused by homerun itself have summaries starting `homerun error:`.
- Secret values are never written to disk, argv or logs, and are masked in every stored log and check-run output. Check-run text may be public.
- GitHub counts `skipped` as passing: homerun never closes a check `skipped` when its job's result is unknown.
- Code comments carry "why" only.
- Every task: failing test first; then `go vet ./...`, `go test -count=1 ./...`; tasks in `internal/daemon` also `go test -race -count=3 ./internal/daemon/`. Never run go test commands concurrently (memory).
- Commits: `export SSH_AUTH_SOCK=~/.1password/agent.sock`; message as given; no attribution lines; never stage `.claude/settings.json` or `.beads/issues.jsonl`.

## Review Focus

1. A secret command's stderr echoes the secret (`sh -c 'echo $TOKEN >&2; exit 1'`): it must never reach a check run, only the local terminal (doctor / CLI). Pinned in Task 1.
2. A user presses `r` in the TUI on a commit whose run already finished: the rerun must still start (dedupe applies only to active runs). Pinned in Task 4.
3. Two workflow files both named `CI` with a job `test`: two distinct checks on GitHub and two distinct log tags, and one failing is visible. Pinned in Task 3.
4. GitHub is down when a setup-failure check is created and stays down past retries: after it recovers, the check is completed, also across a daemon restart. Pinned in Task 5.
5. A force-pushed, garbage-collected commit stuck in requeue: the daemon stops retrying it and the commit is no longer blocked forever. Pinned in Task 6.

### Task 1: Show a secret command's error locally (homerun-7re.30)

**Files:** `internal/config/secret.go`, `internal/config/config_test.go` (or the existing secret test file), `internal/setup/doctor.go`, `cmd/homerun/main.go`.

**Decision:** the error returned by `Secret.Resolve` stays free of the command's output (it can reach public check summaries via `internal/daemon/execute.go` secrets → `failSetup`). Add a separate, local-only detail.

- [ ] Write failing tests:
  - `Resolve` of `{cmd: "echo oops-detail >&2; exit 3"}` returns an error whose `Error()` does **not** contain `oops-detail`, and `config.Detail(err)` returns `oops-detail`.
  - `Detail` of an error from `{cmd: "printf 'line1\nline2\n' >&2; exit 1"}` returns only `line1`; a 500-character first line is cut to at most 200 characters; control characters / escape sequences are removed (use `termsafe.Line`).
  - `Detail(nil)` and `Detail` of a non-command error return "".
- [ ] Implement: in `Resolve`, on `*exec.ExitError`, wrap in an unexported error type that keeps `ee.Stderr` but formats as today (`command failed: exit status N`) and `Unwrap`s to the original. `func Detail(err error) string` uses `errors.As` to find it and returns the sanitised, truncated first non-empty stderr line.
- [ ] Use it where the output stays on this machine: `setup/doctor.go` (the "GitHub App private key source resolves" check prints `: <detail>` after the error when non-empty) and `cmd/homerun/main.go` where `app.private_key` errors are reported. Do **not** use it in `internal/daemon`.
- [ ] Add a doctor test (or extend one) showing the detail appears in doctor output.
- [ ] Gates; commit `fix: config: show a secret command's error on this machine`.

### Task 3: Distinct check names across workflows (homerun-7re.26, homerun-1in.12)

**Files:** `internal/daemon/daemon.go` (`plan()` ~:493-530), `internal/daemon/execute_test.go` or `daemon_test.go`.

**Decision:** names stay `homerun / <workflow name> / <job>` unless two planned checks of one run would share a name; then every colliding check uses the workflow **file path** instead of its `name:` (`homerun / .github/workflows/nightly.yml / test`). Extra checks (`homerun / checks / <name>`) keep their names; a workflow check that collides with an extra check is the one renamed. Log tags already derive from check names (`tagFor`), so they become distinct automatically.

- [ ] Failing tests:
  - Two workflow files `ci.yml` and `ci2.yml`, both `name: CI`, both with job `test`; act output fails one. Expect two checks named `homerun / .github/workflows/ci.yml / test` and `homerun / .github/workflows/ci2.yml / test`, one failure and one success, and distinct `LogPrefix` values on the stored run that match their run-log lines.
  - A workflow `name: checks` with job `lint` plus repo config `checks: {lint: "true"}`: the extra check keeps `homerun / checks / lint`; the workflow check is `homerun / <its path> / lint`.
  - No collision: names unchanged (existing tests keep passing).
- [ ] Implement in `plan()` after collecting checks: count names; for colliding workflow checks set `Name = CheckName(w.Path, jobName)`. Keep matrix-leg `#n` de-duplication as is.
- [ ] Gates; commit `fix: daemon: disambiguate checks whose workflows share a name`. Close homerun-1in.12 with .26.

### Task 4: One active run per commit and event (homerun-7re.28)

**Files:** `internal/daemon/daemon.go` (`start()` ~:390-471, `awaitingRequeue` ~:338 as a template), `internal/daemon/http.go` (`handleStart` ~:54), tests in `internal/daemon/http_test.go` / `daemon_test.go`.

**Decision:** in `start()`, after taking the per-repo lock and before any fetch or claim, under `d.mu`, refuse to start when `d.runs` holds a run with the same `Repo`, `Event.SHA` and `Event.Key()` whose status is `queued` or `running`. Return that existing run (or its ID) so callers can report it. Finished (`done`/`cancelled`) runs do **not** block: a manual rerun of a finished commit must still start. `requeue` runs are already handled by `awaitingRequeue`.

- [ ] Failing tests:
  - Occupy slots (`h.occupySlots`), push a commit, poll (run queued), then POST a manual run of the same branch: the response returns the existing run's ID with a message like `already running as run <id>`, and only one run exists for that SHA.
  - Manual run first (queued), then poll the same head: no second run is created.
  - A manual run of a commit whose previous run is `done` starts a new run (the rerun case).
- [ ] Implement the check in `start()` and surface it in `handleStart` (`StartResponse{RunID: existing, Message: "already running as run <id>"}`); the poll path simply does nothing for that event.
- [ ] Gates including race; commit `fix: daemon: never start a second run while one is active for the same commit`.

### Task 5: Setup-failure checks are never left queued (homerun-7re.23)

**Files:** `internal/store/store.go` (`State`), `internal/daemon/daemon.go` (`singleCheck` ~:562-575, `flushReports` ~:783, `failSetup` ~:553), tests.

**Decision:** the partial-claim cleanup in `start()` already persists failed updates through `store.Check.Pending` and needs no change. `singleCheck` has no run to hang `Pending` on: add `Pending []PendingCheck` to `store.State` (`PendingCheck{Repo string; ID int64; Update gh.Update}`), saved with `SaveState`. When `singleCheck`'s final `UpdateCheck` fails after `gh.Retry`, append it there and save; `flushReports` also re-sends these (once per poll and at startup recovery), removing each on success.

- [ ] Failing tests:
  - Force a setup failure (e.g. a workflow that fails to parse) with `h.rep.failUpdates(n)` large enough that `singleCheck`'s update fails: the `homerun` check is queued on the fake; after failures stop, the next `h.poll()` completes it as failure.
  - The pending entry survives a daemon restart (new daemon on the same state dir) and is flushed by recovery.
  - A successful update leaves `State.Pending` empty.
- [ ] Implement; keep updates idempotent (re-sending a completion is safe).
- [ ] Gates including race; commit `fix: daemon: re-send setup-failure check updates GitHub did not accept`.

### Task 6: Give up on requeued commits that cannot be fetched (homerun-7re.24)

**Files:** `internal/store/store.go` (`Run`), `internal/daemon/daemon.go` (`requeue()` ~:900-938, `start()` fetch ~:404-418), tests in `internal/daemon/recover_test.go`.

**Decision:** add `Requeues int` to `store.Run`. Each failed requeue attempt increments it and saves the run. When the error is the "not fetchable" fetch failure and either `Requeues >= 20` or `time.Since(run.Created) > 24h`, stop: report a `homerun` setup failure on the commit through `failSetup`-style reporting with summary `homerun error: commit <sha7> can no longer be fetched (force-pushed or deleted); not running it`, then set the run `cancelled` so it no longer blocks the event (`awaitingRequeue`). Other errors keep retrying as today. Make the fetch failure detectable (a sentinel error, e.g. `errUnfetchable`, wrapped with `%w`).

- [ ] Failing tests:
  - A requeue run whose SHA does not exist in the source repo: after 20 polls (or with `Created` set 25h ago, one poll) the run is `cancelled`, a `homerun` check with the summary above exists on that SHA, and a further poll does not retry it.
  - Below the cap it is still retried (status stays `requeue`, `Requeues` increments).
  - A requeue run that fails for a different reason is not given up early.
- [ ] Implement.
- [ ] Gates including race; commit `fix: daemon: stop requeueing commits that can no longer be fetched`.
