homerun TUI reference

The target design for homerun's terminal UI: a dashboard of PR searches for the picked repo, dressed as a ballpark at night, with a tabbed preview you can move into the way you move between lazygit's panels. Each screen is drawn the way homerun will render it at about 120×36 unless marked otherwise, in the night-game look that ships before part 2. gh-dash was the inspiration for how readable it is, not for how it looks.

Principles

Search first

Every PR tab is a saved GitHub search, scoped to the picked repo. / edits the current tab's query in GitHub's own syntax, so nothing new has to be learned.

Move in, not just look

The preview is a section you can enter. l or enter goes in, h or esc comes out, one level at a time. A breadcrumb always says where you are.

Width goes to the work

Lists stay narrow. A diff, a log or a check tree takes the whole screen and the PR list steps aside until esc.

Local and GitHub, side by side

homerun's own checks and GitHub-hosted ones share one list, each with its source. A PR homerun has not run on says so instead of looking broken.

The look: a night game

  • Readable first. gh-dash taught the qualities: crisp type, clear sections, no heavy boxes, two-line rows, icons for labels, plain status words. The identity is homerun's own.
  • A scoreboard on top. The strip reads HOMERUN, the repo, then a line score in bulb amber: PRs, runs, passes and failures, the engine's light. There is no status band at the bottom.
  • Tabs are bases. ◆ in clay is the base you are on; the rest are hollow ◇. No filled chips, no underlines.
  • Chalk foul lines. Sections are split by dashed chalk lines. The focused section's line turns infield clay, the one accent.
  • The batter's box. The selected row gets a clay bar in the left gutter and a faintly lit field behind it, never a full highlight.
  • Scoreboard tiles. States are small square all-caps tiles: OPEN, DRAFT, MERGED. Green is safe, red is out, stadium yellow is still in play, amber is only for numbers.
  • The dugout line. Key hints sit on one quiet line at the bottom; every key lives in ?.

Palette and icons

homerun draws with exact truecolor values, so it looks the same in every terminal. On a light terminal background it plays a day game: the light palette, picked by itself (Lip Gloss reports the background). Choosing your own colours stays out of scope.

Structure

  • Top to bottom: the scoreboard strip, the bases (tabs), the body, the dugout line.
  • Dividers are dashed chalk: under the bases, between table and preview, above the dugout line. The focused section's line is clay.
  • Drill-down views replace the bases with a breadcrumb on a clay line: #41 › CI / e2e › go test ./....
  • Square tiles are the only framed shapes in the body: states and check sources.
  • Dialogs and the repo picker float in one square clay border. The scoreboard view keeps its own art.

Icons

Config icons: nerd | unicode | ascii, default nerd. A terminal cannot report its font, so homerun cannot pick for you; homerun doctor and ? mention the setting. Every icon is exactly one cell in every mode, so columns never move. The toggle in the contents switches every screen on this page.

Motion and the ballpark

Baseball lives in motion and empty states only; statuses keep plain words (queued, running, failed). Every animation lasts about a second, never blocks a key, and plays once, except the loading runner. animations: on | reduced | off in config; reduced keeps the runner and banners and drops movement.
